# audit-platform 后端开发约定（各模块共用）

> 所有模块都按这份约定写。事实源是 [`API.md`](API.md)（端点、字段、错误码）与
> [`设计文档.md`](设计文档.md)（业务语义）。

## 分层

```
handlers      HTTP 参数解析、响应映射、AuthContext 提取、权限判定
   ↓
service       业务编排、状态流转、事务边界、保存前校验、审计写入
   ↓
repositories  SQL 与外部系统交互（只用 sqlx 运行时查询）
```

路由集中在各模块 `routes.rs` 的 `pub fn configure(cfg: &mut web::ServiceConfig)`。

## 响应

- 成功：`crate::response::ok(data)` → `ApiResult<T>`
- 列表：`ok(Page::new(items, total, page, page_size))`
- 列表入参：`web::Query<ListQuery>`，`ListQuery::filter("status")` 取 `filter[status]`，
  `ListQuery::filter_list("status")` 取多选，`ListQuery::sort_field(&["created_at"], ("created_at", true))` 取排序。

## 错误

只用 `crate::error::ApiError` 的构造器，错误码必须取自 `API.md` 的错误码表：

```rust
ApiError::bad_request("说明")
ApiError::invalid_param("说明", vec![FieldError::new("field", "原因")])
ApiError::unauthorized("UNAUTHORIZED", "说明")
ApiError::forbidden("PERM_DENIED", "说明")
ApiError::not_found("说明")
ApiError::conflict("CODE_CONFLICT", "说明")
ApiError::conflict_with("CODE_CONFLICT", "说明", json!({...}))
ApiError::unprocessable("INVALID_SQL", "说明")
ApiError::unprocessable_with("DEPENDENCY_MISSING", "说明", json!({...}))
ApiError::rate_limited("说明", 30)
ApiError::internal("说明")
```

禁止把 SQL 片段、堆栈或内部错误原文返回给调用方。

## 鉴权

handler 参数里用 `AuthContext` 提取器（`src/middleware.rs` 的 `FromRequest` 实现）：

```rust
async fn handler(
    ctx: AuthContext,
    state: web::Data<AppState>,
    path: web::Path<u64>,
) -> ApiResult<Json<serde_json::Value>> {
    ctx.require_permission("project:read")?;   // 功能权限
    ctx.require_project(*path)?;                // 项目数据权限
    ...
}
```

权限码见 `backend/db/seed.sql` 的 `permission` 表：
`project:read|write|delete`、`project:config:read|write|reveal`、
`audit:read|write|delete`、`rule:read|write`、`route:read|write`、`trigger:read|write`、
`task:read|retry|stop|review`、`recycle:read|restore|purge`、
`audit_log:read|export`、`metrics:read`、`user:read|write`、`apiclient:read|write`。

路径里没有 project_id 的端点（如 `/audits/{aid}`），在 service 里解析出所属项目后再
`ctx.require_project(project_id)`。

## SQL

```rust
// ✅ 运行时查询
let rows = sqlx::query_as::<_, ProjectRow>("SELECT ... WHERE id = ?")
    .bind(id)
    .fetch_all(&state.db)
    .await?;
```

- **禁止 `query!` / `query_as!` 宏**（编译期要 DATABASE_URL，会让构建失败）。
- 行结构复用 `src/models/**` 里已定义的 `FromRow` 结构体，不要另起一套。
- 时间列用 `chrono::NaiveDateTime`（库里按 UTC 存）；JSON 列用 `serde_json::Value`。
- 事务：`let mut tx = state.db.begin().await?;` … `tx.commit().await?;`

## 审计日志

在模块的 `repositories.rs` 里提供公共函数：

```rust
pub async fn write_audit_log(state: &AppState, entry: AuditLogEntry) -> Result<(), ApiError>
```

`AuditLogEntry` 在 `src/models/ops.rs`。`action` 取值见 `frontend/src/utils/labels.ts` 的
`auditActionLabel` 映射表（如 `PROJECT_CREATE` / `CONFIG_UPDATE` / `RECYCLE_PURGE`）。

## 指标

```rust
state.metrics.inc("audit_task_received_total", vec![("project".into(), pid.to_string())]);
```

## 代码风格

- 注释与文案一律中文。
- 不在可能失败的地方 `unwrap()`；用 `?` 配 `ApiError`。
- `cargo fmt` 风格；函数名与变量名用英文，注释用中文。

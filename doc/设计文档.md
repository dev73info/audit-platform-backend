## 0. 术语表

| 术语 | 含义 |
|---|---|
| 项目（Project） | 系统与外部业务方的隔离边界。配置、连接、队列、Worker、配额、日志均按项目隔离 |
| 审核定义（Audit Definition） | 某个业务场景下的一条审核流程配置，含媒体类型、触发源、规则集、结果路由 |
| 触发源（Trigger Source） | 任务进入系统的入口：Redis 队列 / 轮询接口 / WebSocket / 开放 API |
| 审核任务（Audit Task） | 一次具体的审核执行实例，以 `task_no` 唯一标识 |
| 规则（Rule / Rule Group） | 用于对任务内容做判定的条件集合，支持 AND/OR 逻辑与优先级 |
| 结果路由（Result Route） | PASS / REJECT / REVIEW 三条结果路线各自的动作编排 |
| 动作（Action） | 路由命中后执行的具体副作用：HTTP API、Redis 命令、MySQL 更新、Webhook、消息队列 |
| 幂等键（dedupe_key / dedupe_hash） | 由项目 + 审核 + 来源 + 业务键 + 媒体指纹生成的去重哈希，用于拦截重复任务 |
| 待议（REVIEW） | 自动审核无法判定的中间态，转入人工复核队列 |
| 回收站（Recycle Bin） | 项目 / 审核等对象的软删除暂存区，支持恢复与永久删除 |
| 配额（Quota） | 项目级资源上限：并发任务、QPS、Redis 连接数、MySQL 连接池、媒体大小 |
| 控制面（Control Plane） | 管理后台与配置类接口，负责"定义" |
| 数据面（Data Plane） | 项目运行时组件：队列、Worker 池、连接池，负责"执行" |
| 死信（Dead Letter） | 重试次数耗尽或不可恢复失败的任务终态，需人工介入 |

## 1. 项目概述

### 1.1 背景与要解决的问题

多条业务线（内容社区、电商商品、直播、UGC 上传等）都需要"内容先审后发"能力，但各自建设会带来三类重复成本：

1. **重复建设**：每个业务都要重新实现队列消费、去重、规则判定、结果回调、重试与死信。
2. **资源互相拖累**：多业务共用一套连接与队列时，某个业务的流量高峰或异常规则会拖垮其他业务。
3. **配置不可复用**：审核规则、第三方审核 API、结果回调散落在各业务代码中，变更成本高、不可审计。

本系统的定位是：**一套可多项目独立运行、全配置化的通用审核中台**。管理人员在后台创建项目、配置该项目独有的 Redis / MySQL / 第三方 API 连接，再按业务场景定义审核流程；业务方通过四种触发方式之一提交内容，系统自动完成去重、规则判定、媒体审核、结果路由与动作执行，并把结果通过 API / Redis / MySQL / Webhook 回写。

### 1.2 目标与非目标

**目标**

- 一个系统同时支撑 N 个项目，项目之间在配置、连接、队列、Worker、限流、锁、日志七个维度互相隔离。
- 审核流程 100% 配置化：触发源、规则、媒体类型、结果路由、动作均可在后台调整，无需发版。
- 支持四种触发方式（Redis 队列、轮询接口、WebSocket、开放 API）与三类媒体（文本、图片、视频）。
- 审核结果固定为三条路线：通过（PASS）、不通过（REJECT）、待议（REVIEW），每条路线动作可独立编排。
- 提供完整的回收站、筛选排序、审计日志与监控告警能力。

**非目标（本期不做）**

- 不训练、不托管具体 AI 审核模型（以调用第三方审核 API / 内部模型服务为主）。
- 不建设复杂人工标注平台（仅提供轻量待议复核队列）。
- 不做计费系统与多租户商业化账单（但保留配额与用量统计字段以满足后续扩展）。

### 1.3 成功指标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 开放 API 提交耗时 | P95 < 300ms | 仅指接口受理并返回 task_id，不含审核执行 |
| 列表查询耗时 | P95 < 1s | 单页 20 条、带组合筛选条件 |
| 核心服务可用性 | ≥ 99.9% | 控制面 + 引擎 + Worker |
| 重复任务拦截率 | 100% | 同 dedupe_key 在去重窗口内不产生第二个任务 |
| 单项目故障扩散 | 0 项目 | 单项目积压/异常不影响其他项目吞吐 |
| 动作最终成功率 | ≥ 99.5% | 含自动重试后 |
| 配置变更可追溯率 | 100% | 所有配置变更均有审计日志与版本号 |

### 1.4 设计原则

| 原则 | 具体约束 |
|---|---|
| 项目隔离优先 | 配置、队列、连接池、Worker 池、限流、锁、日志全部按 project_id 隔离；跨项目查询必须显式指定项目 |
| 幂等与可追溯 | 每个任务有 dedupe_hash、幂等锁、幂等记录；状态变更全链路审计；日志可通过 task_id 全链路追踪 |
| 配置化路由 | PASS / REJECT / REVIEW 三条路线动作可独立配置，支持多动作、顺序/并行、参数模板 |
| 失败可控 | 动作失败可重试、可进死信、可转待议；绝不因单点动作失败丢失审核结果 |
| 列表高效易用 | 筛选、排序、分页、列设置、保存视图、批量操作、回收站形成统一闭环 |
| 美观简洁 | 中性色底 + 品牌色点缀；列表密度适中；状态语义用色严格统一（绿=通过、红=不通过、橙=待议） |
| 安全默认开启 | 密钥加密存储、界面脱敏、二次确认、防重放、SSRF 防护、最小权限 |

## 2. 角色与权限

### 2.1 角色定义

| 角色 | 定位 | 数据范围 |
|---|---|---|
| 超级管理员 | 系统全局管理者 | 全部项目 |
| 项目管理员 | 单个或多个项目的负责人 | 被授权的项目 |
| 审核配置员 | 负责审核流程配置 | 被授权的项目（不含连接密钥修改权） |
| 审核员 / 复核员 | 处理待议、人工复核 | 被授权的项目 |
| 只读用户 | 观察、排障、审计 | 被授权的项目 |
| API 客户端 | 业务系统接入方 | 所属项目的开放 API 范围 |

### 2.2 权限模型

采用 **RBAC（角色-权限） + 项目数据权限（Project Scope）** 双层模型：

- **功能权限**：`role → permission` 决定能否调用某个接口（如 `project:config:write`、`task:retry`）。
- **数据权限**：`user → project_ids` 决定能看到哪些项目的数据；所有管理接口强制校验 `project_id` 在授权范围内，缺失或越权一律 403。
- **字段权限**：连接密码、Secret 等敏感字段默认不返回；审核配置员可读到脱敏值但不可修改，项目管理员修改需二次确认。
- **环境权限**：生产环境项目的写操作可额外要求二次确认或更高角色（可配）。

**鉴权伪代码**

```
func Authz(user, project_id, permission):
    if not RoleHasPermission(user.role, permission): return 403 PERM_DENIED
    if not ProjectInScope(user, project_id):        return 403 PROJECT_OUT_OF_SCOPE
    if permission.is_sensitive and not user.mfa_passed: return 401 MFA_REQUIRED
    return OK
```

### 2.4 敏感操作二次确认清单

以下操作必须弹窗二次确认（危险操作使用红色主按钮），且写入审计日志：

1. 修改 / 重置连接密码、API Secret、AppKey Secret
2. 停用项目、停用审核、停用触发源（会中断线上流量）
3. 删除项目 / 审核（进入回收站）
4. 回收站永久删除（需手动输入对象名称确认）
5. 运行中任务强制停止
6. 手动重试动作（可能产生重复副作用，需提示"请确认目标接口幂等"）
7. 批量操作影响条数 > 50

## 3. 总体架构

### 3.1 分层与职责

| 层级 | 组件 | 职责 | 关键约束 |
|---|---|---|---|
| L1 管理后台 UI | Web 控制台 | 登录、项目、配置、审核、任务、回收站、日志、监控 | 所有写操作需确认 + 审计 |
| L2 控制面 API | admin-api | 认证、项目、配置、审核定义、规则、回收站、审计、指标查询 | RBAC + 项目数据权限 |
| L3 开放 API 网关 | open-gateway | 提交、查询、轮询、回调注册、WebSocket、签名校验、限流 | 不直连业务库；签名 + 防重放 |
| L4 审核流程引擎 | audit-engine | 触发接收、去重锁、任务创建、规则执行、媒体审核、结果路由、动作执行 | 幂等、可重试、可追踪 |
| L5 项目数据面 | project-runtime | 项目级 Redis 前缀、MySQL 连接池、Worker 池、队列、限流器、锁 | 项目间零共享 |
| L6 存储层 | MySQL / Redis / 对象存储 | 系统库、项目库、队列与锁、媒体文件 | 媒体按项目目录隔离 |
| L7 可观测层 | 日志 / 指标 / 告警 / 审计 | 全链路追踪、指标采集、告警、审计留存 | 日志带 task_id 与 project_id |

### 3.3 多项目独立运行设计（七类隔离）

| 隔离维度 | 实现方式 | 验收口径 |
|---|---|---|
| 配置隔离 | `project_config` 按 `project_id + type` 存储；密钥使用 KMS/对称加密后落库，按项目独立密钥派生 | 读取 A 项目配置不会触达 B 项目数据 |
| 队列隔离 | Redis 键前缀 `audit:{project_id}:queue:{audit_id}`，Stream + 消费组；或独立 Redis 实例（可配） | A 项目积压不影响 B 项目消费延迟 |
| 连接池隔离 | 每个项目独立 MySQL 连接池实例（HikariCP 级别的独立池），池之间不共享连接 | A 项目池耗尽不会占用 B 项目连接 |
| Worker 隔离 | 每项目独立 Worker 池与并发信号量；调度器按项目轮询分发，单项目满负载不抢占其他项目时间片 | 单项目满负载时其他项目 P95 无明显变化 |
| 限流隔离 | 项目级令牌桶：QPS、并发任务数、媒体大小、第三方 API 调用次数 | 超限仅拒绝该项目请求并告警 |
| 锁隔离 | 幂等锁键 `audit:{project_id}:lock:{dedupe_hash}`；配置热更新锁按项目 | 跨项目不会互相阻塞 |
| 日志隔离 | 日志、审计、指标均带 `project_id` 标签；可按项目开关采样率与留存期 | 可按项目检索与出报表 |

**项目级开关**

- `paused`：暂停后停止消费队列、拒绝开放 API 提交（返回 `PROJECT_PAUSED`），已在处理任务执行完当前步骤后挂起。
- `read_only`：允许查询，禁止所有写操作（用于故障排查期）。
- `rate_override`：运维临时调整限流值（有生效时间与操作审计）。

### 3.4 配额模型与校验算法

**项目配额字段**（`resource_quota`）

| 字段 | 含义 | 默认值 | 校验规则 |
|---|---|---|---|
| max_concurrency | 最大并发处理任务数 | 50 | 1 ≤ x ≤ 5000 |
| max_qps | 提交侧最大 QPS | 100 | 1 ≤ x ≤ 10000 |
| max_mysql_pool | MySQL 最大连接数 | 20 | 1 ≤ x ≤ 200，且 ≤ `system.max_mysql_conn * 80% / 活跃项目数` 的软限制提示 |
| max_redis_conn | Redis 最大连接数 | 20 | 1 ≤ x ≤ 500 |
| max_media_size_mb | 单媒体大小上限 | 50 | 1 ≤ x ≤ 2048 |
| max_daily_tasks | 日任务量上限（可选） | 不限 | 超限时拒绝并告警 |
| max_api_call_per_task | 单任务第三方 API 调用上限 | 10 | 防止规则/动作循环放大 |

**全局校验算法（保存配置时执行）**

```
输入：项目 P 申请 max_mysql_pool = N
1. sum_other = Σ(其他 ACTIVE 项目.max_mysql_pool) + Σ(控制面自身预留连接数)
2. global_limit = floor(system.max_mysql_connections * 0.8)
3. if (sum_other + N) > global_limit:
     拒绝保存，返回 GLOBAL_POOL_EXHAUSTED，
     并提示：当前已分配 sum_other / global_limit，剩余可分配 = global_limit - sum_other
4. if N > P.quota_hard_limit: 拒绝，返回 QUOTA_EXCEEDED
5. else: 通过，写入配置并生成新 version
```

**运行期超限时行为**：不挤占其他项目连接 → 直接拒绝新任务（状态 `REJECTED_BY_QUOTA`）并触发告警 → 任务进入等待队列（可配等待时长，默认 60s）→ 超时转死信。

### 3.5 Redis 键空间规范

| 键模式 | 类型 | 用途 | TTL |
|---|---|---|---|
| `audit:{pid}:queue:{aid}` | Stream | 项目-审核任务队列 | 无（按长度裁剪 MAXLEN） |
| `audit:{pid}:queue:{aid}:dlq` | Stream | 死信队列 | 无 |
| `audit:{pid}:lock:{dedupe_hash}` | String | 幂等锁（值为 worker_id + 租约时间戳） | 默认 300s，续租 |
| `audit:{pid}:idem:{dedupe_hash}` | String | 幂等记录快查（值为 task_id + status） | 与去重窗口一致（默认 24h） |
| `audit:{pid}:rate:{scope}` | String/Hash | 令牌桶计数 | 窗口长度 |
| `audit:{pid}:cursor:{source_id}` | String | 轮询触发源游标 | 无 |
| `audit:{pid}:cfg:version:{type}` | String | 配置版本号（热更新触发） | 无 |
| `audit:{pid}:metric:{minute}` | Hash | 分钟级指标聚合（可选） | 2h |

> 规范：所有键必须带 `audit:{pid}:` 前缀；禁止使用 `KEYS` 命令；批量扫描使用 `SCAN`；Lua 脚本仅用于原子的"判断+写入"组合操作。

### 3.6 任务状态机

```
                         ┌─────────────┐
   触发到达 ────────────▶│  RECEIVED   │
                         └──────┬──────┘
                                │ 鉴权/校验通过，获取幂等锁
                         ┌──────▼──────┐     锁冲突 ──▶ DUPLICATED（终态，记录来源）
                         │   LOCKED    │
                         └──────┬──────┘
                                │ 建任务成功
                         ┌──────▼──────┐
                         │   QUEUED    │◀── 配额等待（WAITING_QUOTA，可选子态）
                         └──────┬──────┘
                                │ Worker 领取
                         ┌──────▼──────────┐
                         │   PROCESSING    │ 拉取内容
                         └──────┬──────────┘
                                │
                         ┌──────▼────────────┐
                         │ RULE_EVALUATING   │ 规则组求值
                         └──────┬────────────┘
                                │
                         ┌──────▼────────────┐
                         │ MEDIA_REVIEWING   │ 文本/图片/视频审核
                         └──────┬────────────┘
                                │
                         ┌──────▼──────┐
                         │  ROUTING    │ 命中 PASS / REJECT / REVIEW
                         └──┬───┬───┬──┘
              PASS ─────────┘   │   └──────── REVIEW
                    ┌───────────▼────────┐  ┌─▼──────────────┐
                    │  执行动作（编排）   │  │ REVIEW_PENDING │
                    └───────────┬────────┘  └─┬──────────────┘
                       成功 ─────┤            │ 人工复核
                                │            ├──▶ PASS ──▶ 执行 PASS 动作 ──▶ SUCCESS
              ┌─────────▼─────────┐          └──▶ REJECT ▶ 执行 REJECT 动作 ▶ SUCCESS
              │      SUCCESS      │
              └───────────────────┘
        失败且可重试 ──▶ 回到 QUEUED（retry_count+1，指数退避）
        失败且不可重试 / 重试耗尽 ──▶ FAILED ──▶ DEAD_LETTER
        REJECT 结果 ──▶ 动作执行完成后终态仍记为 SUCCESS（流程成功），result=REJECT
```

**状态说明表**

| 状态 | 含义 | 是否终态 | 允许的后续 |
|---|---|---|---|
| RECEIVED | 已接收，尚未取到锁 | 否 | LOCKED / DUPLICATED / REJECTED_BY_QUOTA |
| LOCKED | 已获得幂等锁，待建任务 | 否 | QUEUED / DUPLICATED |
| QUEUED | 已入项目队列 | 否 | PROCESSING |
| WAITING_QUOTA（子态） | 配额不足排队等待 | 否 | QUEUED / DEAD_LETTER |
| PROCESSING | 内容拉取中 | 否 | RULE_EVALUATING / FAILED |
| RULE_EVALUATING | 规则求值中 | 否 | MEDIA_REVIEWING / ROUTING / FAILED |
| MEDIA_REVIEWING | 媒体审核中 | 否 | ROUTING / REVIEW_PENDING / FAILED |
| ROUTING | 执行结果路由动作中 | 否 | SUCCESS / REVIEW_PENDING / FAILED |
| REVIEW_PENDING | 待议，等待人工复核 | 否 | PASS / REJECT（复核后走对应路由） |
| SUCCESS | 流程执行完成（result 可能是 PASS/REJECT） | 是 | — |
| FAILED | 执行失败（未转死信） | 是（可重试） | QUEUED（手动/自动重试） |
| DUPLICATED | 命中幂等去重，未创建任务 | 是 | — |
| DEAD_LETTER | 重试耗尽或不可恢复失败 | 是（人工介入） | QUEUED（人工重新入队） |

> 注意：`status` 表示流程状态，`result` 表示审核结论（PASS / REJECT / REVIEW / UNKNOWN）。两者分离，避免"REJECT 结果被误认为流程失败"。

## 4. 功能需求详述

### 4.1 登录与安全

#### 4.1.1 登录流程

1. 用户输入账号密码（+ 图形验证码：同账号连续失败 3 次后出现；可选 2FA TOTP）。
2. 服务端校验：密码哈希比对 → 账号状态 → 角色 → 项目授权列表。
3. 成功后下发短期 Access Token（JWT，默认 2h）+ 长期 Refresh Token（默认 7d，可轮换）。
4. 前端存储 Token（HttpOnly Cookie 优先），每次请求携带；刷新令牌使用后立即失效旧值。

**安全策略表**

| 策略项 | 规则 |
|---|---|
| 密码复杂度 | ≥ 10 位，含大小写字母 + 数字 + 特殊字符中的至少 3 类；不得与最近 3 次重复 |
| 失败锁定 | 同账号 5 次失败锁定 15 分钟；同 IP 30 次失败锁定 30 分钟（可配白名单） |
| 会话超时 | 无操作 30 分钟失效；敏感操作前 5 分钟无操作需重新认证 |
| 2FA | 超级管理员强制开启；其他角色可选；开启后敏感操作需 6 位动态码 |
| 传输安全 | 全站 HTTPS（TLS 1.2+）；Cookie 设置 Secure / HttpOnly / SameSite=Lax |
| 密钥存储 | 连接密码、API Secret 使用 AES-256-GCM 加密，密钥由 KMS 托管，按项目派生子密钥 |
| 密钥展示 | 界面默认脱敏（`sk-****abcd`），点击"查看"需二次确认并记录审计 |
| 审计覆盖 | 登录/登出/失败、配置变更、审核增删改、回收站操作、动作重试、API 调用 |

#### 4.1.2 开放 API 安全

- **身份**：`AppKey` 标识客户端，`AppSecret` 仅用于签名不传输。
- **签名**：`Sign = HMAC-SHA256(AppSecret, CanonicalString)`，CanonicalString 由 `Method\nPath\nTimestamp\nNonce\nBodySHA256` 拼接。
- **防重放**：`Timestamp` 与服务端时间偏差 ≤ 5 分钟；`Nonce` 在 Redis 中记录 10 分钟窗口，重复即拒绝（`REPLAY_ATTACK`）。
- **限流**：按 (项目, 客户端, 接口) 三级令牌桶；超限返回 429 + `Retry-After`。
- **SSRF 防护**：第三方 API BaseURL 必须走白名单解析，禁止解析到内网段（10/8、172.16/12、192.168/16、127.0.0.1、169.254/16）；回调地址同理。

#### 4.2.3 删除与回收站流程

```
删除项目
  1. 检查是否存在运行中任务（PROCESSING/QUEUED/REVIEW_PENDING）
     ├─ 有 → 弹窗提示数量，要求选择「暂停并等待完成」或「强制停止」
     └─ 无 → 直接进入下一步
  2. 事务内：project.status = DELETED，deleted_at/deleted_by 写值
  3. 级联软删除：audit_definition → trigger_source → audit_rule → result_route
  4. 写入 recycle_bin 记录（expire_at = now + retain_days）
  5. 停止该项目 Worker 消费、关闭开放 API 提交、释放或标记连接池待回收
  6. 审计日志记录（含快照 JSON，用于恢复校验）
```

- **恢复**：校验编码冲突 → 校验依赖配置完整性（Redis/MySQL 是否仍可连通，缺失则提示先修复）→ 校验配额是否仍满足全局约束 → 恢复状态与关联对象 → 重启 Worker。
- **永久删除**：二次确认输入项目名称 → 创建异步清理任务 → 清理顺序：Redis 队列与锁键 → 媒体文件（对象存储按目录删）→ 任务与日志索引 → 项目元数据 → 保留审计摘要（含对象名、删除人、时间、影响条数）。

### 4.5 触发源管理

#### 4.5.1 四种触发源对比

| 触发源 | 适用场景 | 可靠性 | 实时性 | 关键配置 |
|---|---|---|---|---|
| Redis 队列 | 业务方已在使用 Redis，希望解耦 | 高（消费组 + ACK + 死信） | 秒级 | 队列名、消费组、消费者名、批量大小、可见性超时 |
| 轮询接口 | 业务方只提供查询接口，无推送能力 | 中（依赖游标幂等） | 取决于间隔（10s~5min） | URL、间隔、cursor 字段路径、分页大小、增量字段 |
| WebSocket | 需要长连接低延迟推送 | 中（需业务方实现重连） | 毫秒级 | 认证方式、订阅主题、心跳间隔、单连接限流 |
| 开放 API | 业务方主动提交，需要同步拿到 task_id | 高（签名 + 幂等） | 实时 | AppKey、限流、同步/异步模式、回调地址 |

**优先级**：同一审核配置多个触发源时，按 `priority` 升序调度消费（默认 Redis 队列 priority=10，轮询=20，WebSocket=30，开放 API=40）。优先级仅影响 Worker 拉取顺序，不影响各源自身可靠性。

#### 4.5.2 Redis 队列触发

- 键：`{queue_prefix}:queue:{audit_code}`，类型 Stream，消费组 `cg_{audit_code}`。
- 消费者名：Worker 实例 ID；ACK 在处理成功后发送；PEL 超时（默认 60s）消息由 `XAUTOCLAIM` 重新分配。
- 消息格式（JSON）：

```json
{
  "msg_id": "biz-20261021-0001",
  "biz_key": "post:9527",
  "media": [
    { "type": "text",  "content": "这是一段待审核文本" },
    { "type": "image", "url": "https://oss.example.com/a.jpg" },
    { "type": "video", "url": "https://oss.example.com/v.mp4", "duration": 30 }
  ],
  "ext": { "user_id": "u123", "scene": "ugc_post" },
  "callback": { "url": "https://biz.example.com/cb", "headers": {} },
  "submit_at": 1761000000000
}
```

- 解析失败（非法 JSON / 缺 biz_key）→ 计入错误记录 + 转入 DLQ，不阻塞后续消息。
- 支持"最近消费记录"面板：最近 50 条消息 ID、解析状态、耗时、错误信息。

#### 4.5.3 轮询接口触发

- 按 `interval` 定时拉取：`GET {url}?cursor={cursor}&size={page_size}`。
- 游标取自响应中的 `cursor` 字段路径（可配 JSONPath，如 `$.data.next_cursor`）；首次为空。
- 每条记录用 `biz_key`（可配字段路径）生成 dedupe_key 去重；已存在则跳过。
- 失败处理：连续失败 3 次告警，5 次暂停该源并保留游标（恢复后从断点续拉）。
- 单源分布式锁：同一源同一时刻只允许一个调度实例拉取（Redis 锁，防止重复拉取）。

#### 4.5.4 WebSocket 触发

- 连接：`wss://{host}/ws/projects/{pid}/audits/{aid}?app_key=...&timestamp=...&nonce=...&sign=...`
- 认证失败直接断开（关闭码 4401）；心跳 30s，超时 90s 断开。
- 客户端推送任务消息（同 Redis 消息格式），服务端返回 `ack`（含 task_id）。
- 服务端可主动推送任务结果（若客户端订阅了结果主题）。
- 单项目最大连接数可配（默认 100）；单连接 QPS 限制（默认 50）。

#### 4.5.5 开放 API 触发

见 6.5 节。核心：提交 → 校验 → 幂等锁 → 返回 `task_id` → 异步执行 → 结果可查询 / 可轮询 / 可回调。

#### 4.5.6 触发源通用能力

- 启停开关（暂停后不再接收，已接收消息保留在队列中）。
- 测试按钮：发送一条测试消息，返回完整链路各阶段耗时（不含真实审核结果时可跳过）。
- 最近消费记录：成功/失败条数、最近错误、平均延迟。
- 删除：随审核删除；独立删除需确认无运行中任务。

### 4.6 审核流程引擎（12 步细化）

| 步骤 | 处理内容 | 失败处理 |
|---|---|---|
| 1 接收 | 四源统一适配为内部 `TaskCommand`（含 project_id、audit_id、source_type、source_id、biz_key、media[]、ext） | 解析失败 → 记错误 + DLQ |
| 2 鉴权校验 | API 签名/WS 认证；项目与审核状态校验（PAUSED/DELETED 拒绝）；参数必填与类型校验 | 返回明确错误码，不建任务 |
| 3 生成 dedupe_key | `SHA256(project_id + audit_id + source_type + source_id + biz_key + [media_hash])`；media_hash 由媒体 URL/内容按序拼接后取哈希 | — |
| 4 幂等锁 | Redis `SET key value NX EX 300`；成功者继续；失败者查 `idem` 记录，若已存在任务则标记 DUPLICATED 并复用原 task_id 返回；数据库唯一索引 `(project_id, dedupe_hash)` 兜底 | 唯一索引冲突 → 视为重复，返回已存在任务 |
| 4b 锁续租 | Worker 每 60s（TTL 的 1/5）续租一次；任务完成或失败时释放（Lua 校验 value 后再删，避免误删他人锁） | 续租失败 → 告警并标记任务可能重复执行，人工介入 |
| 5 建任务入队 | 写 `audit_task`（status=QUEUED），写入项目 Stream 队列 | 写库失败 → 释放锁，返回 5xx，客户端可重试 |
| 6 Worker 消费 | 项目 Worker 池按 `XREADGROUP` 批量拉取（批量 1~32），获取并发信号量 | 信号量不足 → 等待；超时 → 重新入队 |
| 7 内容拉取 | 从消息体、Redis、项目 MySQL 或第三方 API 获取媒体内容；图片/视频下载到对象存储项目目录并计算 hash | 拉取超时 → 重试；重试耗尽 → FAILED → DLQ |
| 8 规则执行 | 按规则组优先级求值，详见 4.7 | 规则异常（表达式错误）→ 跳过并记录，默认转 REVIEW |
| 9 媒体审核 | 文本/图片/视频审核，详见 4.8 | 模型 API 失败 → 熔断/重试；最终失败 → 按 `on_model_fail` 策略（默认转 REVIEW） |
| 10 结果判定 | 汇总规则命中与模型结果，输出 PASS / REJECT / REVIEW | — |
| 11 动作执行 | 按结果路由编排执行动作，详见 4.9 | 按动作 `on_error` 策略：继续 / 终止 / 转待议 |
| 12 收尾 | 回写结果与审计、释放锁、上报指标；失败按重试策略重试，超限进死信 | — |

**并发与顺序保证**

- 同 `biz_key` 的任务通过幂等锁串行化；不同 biz_key 可并行。
- 项目级并发信号量控制同时处理的任务数；审核级并发配额在其之上再限一层。

### 4.7 规则引擎

#### 4.7.1 数据模型

```
audit_rule（规则组）
  ├── priority：数字小者优先
  ├── logic：AND / OR
  ├── stop_on_hit：命中后是否终止后续规则组（默认 true）
  ├── on_hit_result：PASS / REJECT / REVIEW
  └── rule_item[]（条件项）
        ├── field：取值路径（JSONPath 或内置字段）
        ├── operator：比较符
        ├── value：比较值
        └── case_sensitive / negate
```

#### 4.7.2 内置字段

| 字段 | 说明 |
|---|---|
| `media.text` | 全部文本内容拼接 |
| `media.text_len` | 文本长度 |
| `media.count` | 媒体数量 |
| `media.type` | 媒体类型集合 |
| `media.size_bytes` | 总大小 |
| `media.hash` | 媒体指纹 |
| `ext.*` | 业务扩展字段（如 `ext.user_id`） |
| `model.label` | 模型返回标签 |
| `model.score` | 模型置信度（0~1） |
| `model.risk_level` | 归一化风险等级（low/medium/high） |
| `task.source_type` | 触发来源 |
| `task.submit_hour` | 提交小时（用于时段策略） |

#### 4.7.3 操作符

| 类别 | 操作符 |
|---|---|
| 比较 | eq、ne、gt、gte、lt、lte、between |
| 集合 | in、not_in、contains、not_contains、contains_any、contains_all |
| 文本 | starts_with、ends_with、regex、length_gt、length_lt |
| 空值 | is_null、is_not_null、is_empty、is_not_empty |
| 模型 | score_gt、score_lt、label_in、risk_in |

#### 4.7.4 规则配置示例（JSON）

```json
{
  "rules": [
    {
      "name": "命中高危词直接驳回",
      "priority": 10,
      "logic": "OR",
      "stop_on_hit": true,
      "on_hit_result": "REJECT",
      "items": [
        { "field": "media.text", "operator": "contains_any", "value": ["违禁词A", "违禁词B"] },
        { "field": "model.score", "operator": "gte", "value": 0.95 }
      ]
    },
    {
      "name": "低风险快速通过",
      "priority": 20,
      "logic": "AND",
      "stop_on_hit": true,
      "on_hit_result": "PASS",
      "items": [
        { "field": "model.score", "operator": "lt", "value": 0.2 },
        { "field": "media.count", "operator": "lte", "value": 9 }
      ]
    },
    {
      "name": "灰区转待议",
      "priority": 30,
      "logic": "AND",
      "stop_on_hit": true,
      "on_hit_result": "REVIEW",
      "items": [
        { "field": "model.score", "operator": "between", "value": [0.2, 0.95] }
      ]
    }
  ],
  "default_result": "REVIEW",
  "on_model_fail": "REVIEW"
}
```

#### 4.7.5 执行语义

- 未命中任何规则组 → 取 `default_result`（默认 REVIEW，保守策略）。
- 模型不可用 → 取 `on_model_fail`（可选 PASS / REJECT / REVIEW，默认 REVIEW）。
- 规则表达式编译失败 → 该规则组跳过，审计记录 `RULE_COMPILE_ERROR`，不影响其他组。
- 每个规则组求值结果写入任务详情"规则命中"面板（字段、实际值、操作符、期望值、是否命中）。

### 4.8 媒体审核

#### 4.8.1 文本审核

| 环节 | 说明 |
|---|---|
| 预处理 | 去空白、繁转简（可配）、全半角归一、URL/手机号/邮箱脱敏（可配是否保留） |
| 关键词 | 项目级词库（支持分组：违禁/敏感/营销/自定义），支持命中位置返回 |
| 模型 | 调用第三方文本审核 API（从项目 API 配置中选择 `TEXT` 标签的配置） |
| 结果 | 标签 + 分数 + 命中片段；与规则结果合并 |

#### 4.8.2 图片审核

| 环节 | 说明 |
|---|---|
| 下载与校验 | 大小 ≤ max_media_size_mb；格式白名单 jpg/png/webp/bmp/gif（首帧）；校验魔数防伪装 |
| 预处理 | 缩放至长边 ≤ 2048（可配）、压缩、计算 pHash 用于相似图去重 |
| OCR | 可选 OCR 配置，识别结果并入 `media.text` 参与文本规则 |
| 模型 | 鉴黄 / 暴恐 / 政治敏感 / 广告 / 二维码 等标签（按项目选择启用的标签集） |
| 多图 | 逐张审核后取"最严"策略（默认：任一 REJECT 则 REJECT；有 REVIEW 且无 REJECT 则 REVIEW） |

#### 4.8.3 视频审核

| 环节 | 说明 |
|---|---|
| 抽帧 | 默认 1 fps（可配 0.2~5），上限 300 帧；关键帧优先 |
| 音频 | 可选抽取音轨做语音转写后走文本审核 |
| 帧审核 | 帧图片走图片审核流程，批量并发（并发数受项目配额约束） |
| 汇总 | 策略可配：`worst`（最严）/ `majority`（多数）/ `threshold`（命中帧数 ≥ N 判定） |
| 性能 | 大视频走异步媒体处理 Worker；任务页展示进度（抽帧 x/y、审核 x/y） |

#### 4.8.4 相似内容去重（可选）

- 文本：SimHash 汉明距离 ≤ 3 视为相似；图片：pHash 汉明距离 ≤ 5。
- 相似内容在去重窗口内可复用前序审核结果（开关控制，默认关闭以保守为准）。

### 4.9 结果路由与动作

#### 4.9.1 路由结构

```
result_route
  result_type: PASS | REJECT | REVIEW
  exec_mode: sequential | parallel
  on_error: continue | abort | to_review
  actions: [action, ...]
```

#### 4.9.2 动作类型定义

| 类型 | 关键参数 | 幂等建议 |
|---|---|---|
| HTTP API | 选择已配置的第三方 API；method、path、headers、body 模板、超时、重试 | 请求头带 `X-Idempotency-Key: {task_id}` |
| Redis 命令 | 命令白名单：SET / HSET / LPUSH / SADD / ZADD / PUBLISH / EXPIRE / DEL；key 模板、value 模板、TTL | 天然幂等（SET/HSET） |
| MySQL 更新 | 数据源（项目 MySQL）；SQL 模板（仅允许参数化 UPDATE/INSERT，禁止 DDL 与无 WHERE 的 UPDATE）、参数绑定 | 使用 `INSERT ... ON DUPLICATE KEY UPDATE` |
| Webhook | URL（SSRF 校验）、签名方式（HMAC）、body 模板、重试 | 带 task_id 与幂等键 |
| 消息队列 | 目标（Redis Stream / 项目 MQ 配置，若未配置则不可用）、topic、body 模板 | 消费端按 task_id 去重 |

#### 4.9.3 参数模板语法

- 变量：`{{task.id}}`、`{{task.result}}`、`{{task.biz_key}}`、`{{media.url}}`、`{{model.score}}`、`{{ext.user_id}}`、`{{now}}`、`{{now_ms}}`。
- 过滤器：`{{ media.text | truncate:200 }}`、`{{ model.score | round:2 }}`、`{{ ext.user_id | default:'anonymous' }}`。
- 内置函数：`uuid()`、`sha256(x)`、`json_escape(x)`、`url_encode(x)`。
- 模板渲染失败 → 该动作标记失败，按 `on_error` 处理。

#### 4.9.4 动作配置示例（同一 API 不同参数 + 写 Redis/MySQL）

```json
{

  "exec_mode": "sequential",
  "on_error": "to_review",
```

#### 4.9.5 快捷模板

| 模板 | 生成内容 |
|---|---|
| 除通过外均驳回 | REJECT 与 REVIEW 使用同一组动作，PASS 为空 |
| 三条路线相同动作 | PASS/REJECT/REVIEW 复制同一组动作（参数中带 result 变量） |
| 仅回调 | 三条路线各配一个 Webhook 动作 |
| 通过放行 + 待议人工 | PASS 无动作，REVIEW 进入人工复核队列，REJECT 回调并写库 |

#### 4.9.6 动作执行记录与重试

- 每个动作执行写 `action_exec_log`：请求（脱敏后）、响应摘要、耗时、状态、重试次数。
- 失败动作可在任务详情页"手动重试"：更新 `retry_count`，需二次确认提示"请确认目标接口幂等"。
- 动作失败率纳入监控；同一动作连续失败 10 次触发告警并自动暂停对应路线（可配）。

### 4.10 幂等与去重（强化说明）

| 层 | 机制 | 失效兜底 |
|---|---|---|
| 接入层 | dedupe_key 由客户端可选传入 `biz_key`，未传则用 media_hash 兜底 | 无 biz_key 且无 media_hash → 不做去重，标记 `NO_DEDUPE` |
| 锁层 | Redis `SET NX EX`，TTL 300s，value = `worker_id:ts`；Lua 校验后释放 | Redis 不可用 → 降级为数据库唯一索引去重（性能下降，告警） |
| 存储层 | `idempotency_record` 唯一索引 `(project_id, dedupe_hash)` | 唯一索引冲突 → 返回已有任务，标记 DUPLICATED |
| 续租 | 处理中每 TTL/5 续租；进程崩溃后锁自然过期，消息回到 PEL 重新投递 | 重复执行风险由动作幂等键消除 |
| 窗口 | `dedupe_window_sec` 默认 24h；过期记录由清理任务批量删除 | 窗口外的重复提交视为新任务 |

### 4.11 回收站

#### 4.11.1 收录范围

| 对象 | 是否入回收站 | 说明 |
|---|---|---|
| 项目 | 是 | 级联软删除其审核、触发源、规则、路由 |
| 审核定义 | 是 | 级联软删除触发源、规则、路由 |
| 触发源 / 规则 / 路由 | 可选（跟随父级，不单独展示，可通过"包含子对象"开关查看） | 默认不单独占用回收站条目 |

#### 4.11.2 回收站列表字段

名称 / 类型（项目/审核）/ 所属项目 / 删除人 / 删除时间 / 保留期限（剩余天数）/ 状态（可恢复/已过期待清理）/ 关联对象数。

#### 4.11.3 操作规则

- **恢复**：校验编码冲突 → 依赖配置完整性 → 配额 → 通过则恢复父对象与子对象，重启消费。失败时给出具体原因（如"项目编码 xxx 已被占用，请先重命名或永久删除冲突项"）。
- **永久删除**：输入框需完全匹配对象名称 → 创建异步任务 → 进度可在"清理任务"面板查看 → 清理完成后保留审计摘要。
- **批量永久删除**：多选后统一确认，逐项异步执行，失败的单独列出原因。
- **过期自动清理**：定时任务每日扫描 `expire_at < now` 的条目，按项目保留策略执行永久删除（可关闭自动清理，改为仅通知）。
- **回收站项目不可运行**：Worker 不消费、开放 API 拒绝（`PROJECT_DELETED`）、WebSocket 拒绝连接。

**必记事件**

| 类别 | 事件 |
|---|---|
| 认证 | 登录成功/失败、登出、锁定、2FA 开启/关闭 |
| 项目 | 创建、编辑、启停、删除、恢复、永久删除 |
| 配置 | Redis/MySQL/API 配置新增、修改、测试、回滚（记录版本号与 diff 摘要，不含密钥明文） |
| 审核 | 审核定义增删改、启停；触发源增删改启停；规则增删改；路由与动作增删改 |
| 任务 | 创建、重试、强制停止、人工复核结论 |
| 动作 | 动作执行成功/失败、手动重试 |
| 回收站 | 进入、恢复、永久删除、自动清理 |
| API | AppKey 创建/停用、开放 API 调用（抽样或全量，按项目配置）、签名失败、限流拒绝 |

**字段**：`id, project_id, operator, operator_ip, action, object_type, object_id, result(success/fail), detail_json, trace_id, created_at`。

**留存**：默认 ≥ 180 天（可配）；支持导出；审计日志不可通过业务接口删除，仅能由超管按合规流程归档清理。

#### 4.14.2 告警规则与阈值建议

| 告警 | 表达式（示例） | 级别 | 处置建议 |
|---|---|---|---|
| 队列积压 | `audit_queue_backlog > 1000` 持续 5m | P2 | 扩容 Worker 或检查规则耗时 |
| 积压持续增长 | `deriv(audit_queue_backlog[10m]) > 0` 且 > 500 | P2 | 同上 |
| 死信增加 | `increase(audit_dlq_total[10m]) > 10` | P1 | 查看死信原因，修复后重新入队 |
| 动作失败率高 | `rate(audit_action_exec_total{status="fail"}[5m]) / rate(audit_action_exec_total[5m]) > 0.05` | P2 | 检查第三方 API 与模板参数 |
| 连接池超限 | `audit_pool_mysql_in_use / max_pool > 0.9` 持续 3m | P2 | 调整池大小或限流 |
| 连接失败 | `increase(audit_api_call_total{http_status=~"5.."}[5m]) > 20` | P1 | 检查第三方服务与网络 |
| 项目暂停 | `project_status == paused` 且非人为标记 | P3 | 确认是否自动熔断 |
| 锁冲突率 | `rate(audit_lock_conflict_total[5m]) / rate(audit_task_received_total[5m]) > 0.2` | P3 | 检查重复提交来源 |
| 配额触顶 | `audit_quota_usage_ratio > 0.95` | P3 | 评估扩容 |
| 开放 API 错误率 | 5xx 比例 > 2% 持续 5m | P1 | 查网关与下游 |
| 待议堆积 | `audit_task_status_current{status="review_pending"} > 500` | P3 | 增派复核人力 |
| 回收站过期未清理 | 存在 `expire_at < now` 条目超过 7 天 | P4 | 执行清理或调整保留期 |

#### 4.14.3 看板

监控看板分三个视图：

1. **全局视图**（超管）：项目健康度矩阵、总吞吐、Top N 异常项目、资源水位。
2. **项目视图**：该项目任务量趋势、三路线分布饼图、耗时分位、队列积压、动作成功率、连接池水位。
3. **审核视图**：单条审核的吞吐、失败原因 Top、规则命中分布、动作耗时 Top。

```
project 1──N project_config

```

### 5.3 核心 DDL（MySQL 8.0，InnoDB，utf8mb4）

### 5.4 索引与归档策略

| 策略 | 说明 |
|---|---|
| 排序白名单 | 只有进入白名单的字段才允许前端排序，且每个白名单字段必须有对应索引；新增排序字段需评审并加索引 |
| 联合索引顺序 | 遵循"等值筛选 → 范围筛选 → 排序"顺序，如 `(project_id, status, created_at)` |
| 分区 | `audit_task`、`action_exec_log`、`task_event`、`audit_log` 按月 RANGE COLUMNS 分区；每月初由任务自动创建下月分区 |

| 统计 | 列表页的计数与聚合走小时级汇总表（`project_hourly_stat`），避免大表实时 COUNT |
| 软删除索引 | `deleted_at` 单独建索引；列表默认条件 `deleted_at IS NULL` |
| 大字段 | `payload_ref` 只存引用，原始载荷放对象存储；`request_json/response_json` 超过 8KB 截断并标记 |

## 6. API 设计

### 6.1 通用约定

- 管理端前缀 `/api/admin/v1`，开放 API 前缀 `/open/v1`，均使用 HTTPS + JSON（`Content-Type: application/json; charset=utf-8`）。
- 时间字段统一使用毫秒时间戳或 ISO8601（`2026-10-21T10:00:00+08:00`），二选一全站统一（建议 ISO8601）。
- 分页参数：`page`（从 1 开始）、`page_size`（20/50/100）；排序参数：`sort=created_at:desc,result:asc`；筛选参数：`filter[status]=ACTIVE,PAUSED`。
- 统一响应结构：

```json
{
  "code": 0,
  "message": "OK",
  "data": { },
  "trace_id": "8f3c1a9e-...",
  "cost_ms": 42
}
```

列表响应 `data` 结构：

```json
{
  "items": [ ],
  "total": 1234,
  "page": 1,
  "page_size": 20,
  "has_more": true
}
```

- 所有写操作需带 `Idempotency-Key`（可选）与 `X-Trace-Id`（可选，默认服务端生成）。
- 字段校验失败返回 400 + `field_errors` 数组（字段路径 + 原因）。

### 6.2 开放 API 签名算法

```
CanonicalString =
  HTTPMethod + "\n" +
  Path + "\n" +
  Timestamp + "\n" +           // 毫秒时间戳
  Nonce + "\n" +               // 32 位随机串
  SHA256HEX(RequestBody)       // 空 body 用空串的哈希

Sign = HMAC_SHA256(AppSecret, CanonicalString) 的十六进制小写

请求头：
X-Api-Key: {app_key}
X-Timestamp: {timestamp}
X-Nonce: {nonce}
X-Signature: {sign}
```

服务端校验顺序：参数完整性 → AppKey 存在且启用 → 时间偏差 ≤ 5min → Nonce 未重复（Redis 记录 10min）→ 签名比对 → IP 白名单 → 项目状态 → 限流。任一步失败立即返回，不执行业务。

### 6.3 错误码表

| HTTP | code | 含义 | 处理建议 |
|---|---|---|---|
| 400 | `INVALID_PARAM` | 参数校验失败 | 查看 `field_errors` |
| 400 | `INVALID_SIGNATURE` | 签名错误 | 检查 CanonicalString 拼接 |
| 400 | `TIMESTAMP_EXPIRED` | 时间偏差超限 | 校准客户端时间 |
| 400 | `REPLAY_ATTACK` | Nonce 重复 | 重新生成 Nonce |
| 401 | `UNAUTHORIZED` | 未认证/Token 失效 | 重新登录或刷新 Token |
| 401 | `MFA_REQUIRED` | 敏感操作需二次验证 | 提交动态码 |
| 403 | `PERM_DENIED` | 功能权限不足 | 申请角色 |
| 403 | `PROJECT_OUT_OF_SCOPE` | 项目数据权限不足 | 申请项目授权 |
| 403 | `QUOTA_EXCEEDED` | 项目配额超限 | 调整配额或限流 |
| 403 | `GLOBAL_POOL_EXHAUSTED` | 全局连接池不足 | 降低池大小或扩容数据库 |
| 403 | `PROJECT_PAUSED` | 项目已暂停 | 恢复项目 |
| 403 | `PROJECT_DELETED` | 项目已删除 | 从回收站恢复 |
| 404 | `NOT_FOUND` | 对象不存在 | 确认 ID |
| 409 | `CODE_CONFLICT` | 编码冲突 | 更换编码 |
| 409 | `DUPLICATED_TASK` | 幂等命中，返回已有任务 | 直接使用返回的 task_id |
| 409 | `VERSION_CONFLICT` | 配置版本冲突 | 重新拉取后提交 |
| 422 | `CONNECTION_TEST_FAILED` | 连接测试失败 | 检查地址/账号/网络 |
| 422 | `DEPENDENCY_MISSING` | 依赖配置缺失 | 先补齐 Redis/MySQL/API 配置 |

| 503 | `DOWNSTREAM_UNAVAILABLE` | 第三方依赖不可用 | 稍后重试 |

**轮询拉取**：`GET .../poll?cursor={opaque}&size=50`，返回 `items`（已完成的任务结果）、`next_cursor`、`has_more`。游标由服务端生成，客户端不得解析。

**回调**：注册后，任务完成以 `POST` 推送到业务方 URL；`X-Signature` 为 HMAC-SHA256（密钥来自回调配置），body 同查询结果响应；业务方返回 2xx 视为成功，否则按 1s/5s/25s/125s/625s 重试 5 次后转死信并告警。

**WebSocket**：连接后先发 `auth` 帧，服务端回 `auth_ok`；客户端发 `submit` 帧，服务端回 `ack`（含 task_id）；任务完成后服务端主动推 `result` 帧（若订阅）。心跳帧 `ping/pong`，90s 无 pong 断开。

### 6.6 限流规则

| 层级 | 维度 | 默认 | 超限行为 |
|---|---|---|---|

| 开放 API | 单 IP | 200 QPS | 429 |
| WebSocket | 单连接 | 50 msg/s | 断开并告警 |
| 引擎 | 项目并发任务 | max_concurrency | 排队等待 |
| 引擎 | 单审核并发 | audit.concurrency | 排队等待 |
| 引擎 | 第三方 API | 配置中的限流值 | 排队/熔断 |
| 管理端 | 单用户写操作 | 20 次/分钟 | 429（防误操作） |

### 8.4 页面清单与细化

#### P1 登录页

- 居中卡片：Logo、系统名、账号、密码、验证码（失败 3 次后出现）、2FA（开启后显示）、登录按钮、忘记密码入口。

- 安全提示：连续失败提示剩余次数；锁定时显示解锁时间倒计时。
- 移动端：单列堆叠，键盘弹出时按钮不被遮挡。

#### P2 项目列表 / 项目详情

**列表**：字段见表 4.2.2。操作：查看、编辑、配置、启停、删除（进回收站）。队列积压列超阈值显示红色数值 + 警示图标，点击跳转监控看板。

**详情**：Tab 结构 —— 概览（基本信息 + 今日/累计任务量 + 状态分布迷你图 + 队列积压）｜配置（Redis/MySQL/API/配额入口）｜审核（该项目审核列表）｜成员与权限｜最近告警｜审计日志。顶部显示项目状态标签与环境标签；生产环境项目在编辑区顶部显示黄色提示条"当前为生产环境，修改将影响线上流程"。

#### P3 项目配置页

- 左侧二级 Tab：Redis / MySQL / 第三方 API / 对象存储 / 配额 / 成员。

#### P4 审核列表 / 审核编辑

**列表**：名称、编码、媒体类型（多标签）、状态、触发方式（多标签）、今日任务量、通过率、更新时间。操作：查看、编辑、克隆、启停、删除。

**编辑页**：分区表单 ——
1. 基本信息（名称、编码、媒体类型多选、描述）
2. 触发源（卡片列表，可增删排序，每个卡片含类型专属配置与"测试"按钮）
3. 规则配置（规则组列表，支持拖拽调优先级；每个规则组含条件项编辑器：字段下拉 / 操作符下拉 / 值输入；提供"试跑"按钮）
4. 媒体审核设置（按媒体类型 Tab：模型选择、标签集、OCR 开关、抽帧参数、聚合策略）
5. 结果路由（三条路线 Tab，每 Tab 内为动作编排区：动作卡片可拖拽排序、复制、删除；每个动作含类型专属表单；提供"快捷模板"下拉与"预览渲染结果"）
6. 高级设置（超时、重试、去重窗口、并发配额、默认结果、模型失败兜底）

底部固定操作条：保存草稿 / 保存并启用 / 取消。未保存离开时弹窗提示。

#### P5 触发源管理

卡片式列表：每个触发源一张卡，显示类型图标、名称、优先级、状态开关、最近消费时间、成功率迷你趋势、最近错误摘要。卡片右上角"测试/编辑/删除"。卡片下方展开可看最近 50 条消费记录（消息 ID、解析状态、耗时、错误）。

#### P6 规则配置

左侧规则组列表（可拖拽排序、启停、复制），右侧当前规则组的条件编辑器。条件项支持 AND/OR 切换、字段选择器（内置字段树形选择）、操作符下拉、值输入（根据操作符切换为输入框/标签输入/数值范围）。底部"试跑"面板：粘贴样例 JSON 或选择历史任务 → 显示命中链路（每个条件项的实际值、是否命中、最终结论）。

#### P7 结果路由配置

顶部三 Tab：通过 / 不通过 / 待议。每个 Tab 内：执行模式（顺序/并行）、失败策略（继续/终止/转待议）单选，动作列表（拖拽排序）。动作卡片字段按类型动态渲染（见 4.9.2）。提供"参数变量"侧边抽屉，点击变量自动插入当前输入框。"预览渲染"按钮用样例任务渲染最终请求（脱敏展示），确认无误后保存。

#### P8 任务列表 / 任务详情

**列表**：任务号（等宽）、项目、审核、来源类型、媒体类型、结果标签、状态标签、去重标记、耗时、创建时间、完成时间。筛选栏支持任务 ID 精确搜索、耗时范围。

**详情**：上方信息区（任务号 + 状态 + 结果 + 来源 + 耗时 + 重试次数），下方 Tab：
- 概览：关键字段 + 结果原因（模型标签/分数、规则命中）
- 媒体：图片网格预览（点击放大）、视频播放器（带违规时间点标记）、文本内容（命中词高亮）
- 规则命中：规则组与条件项表格（实际值、操作符、期望值、是否命中）
- 动作日志：动作列表（类型、状态、耗时、重试次数、请求/响应折叠查看、重试按钮）
- 时间线：状态迁移流水（时间、状态、耗时、消息）
- 审计：本任务相关审计记录

右上角操作：重试任务、强制停止（仅运行中）、导出详情。

#### P9 待议复核列表

左侧待处理队列（按等待时长排序，超时标红），右侧复核工作台：媒体预览 + 规则命中 + 模型结果 + 历史相似任务参考；底部结论按钮（通过 / 不通过，需选择原因码，可填备注）。支持快捷键：A=通过、R=不通过、N=下一条。复核后自动执行对应路由动作。

#### P10 回收站

顶部 Tab：项目 / 审核 / 全部。列表字段：名称、类型、所属项目、删除人、删除时间、剩余保留天数（≤3 天标红）、状态。操作：恢复、永久删除。永久删除弹窗要求输入对象全名，输入框下方显示"输入 xxx 以确认"；按钮默认禁用，完全匹配后才可点击。清理进行中的条目显示进度条与"查看清理任务"。

#### P11 审计日志

筛选：操作人、操作类型（下拉枚举）、对象类型、对象 ID、项目、时间范围、结果。列表：时间、操作人（含 IP）、操作、对象、结果标签、详情（点击展开 JSON 或 diff 视图）。提供"导出"按钮。页面顶部提示当前留存策略。

#### P12 监控看板

顶部：时间范围选择（1h/6h/24h/7d）+ 项目/审核筛选 + 自动刷新开关。
- 第一排指标卡：任务量、成功率、平均耗时（P50/P95）、待议数、积压数、死信数（环比箭头）。
- 第二排：任务量趋势折线（按结果堆叠）、耗时分布直方图、三路线占比饼图。
- 第三排：队列积压趋势、动作成功率按类型、连接池水位（MySQL/Redis）、配额使用率。
- 底部：活跃告警列表（级别、名称、持续时长、处置建议、跳转）。

## 9. 非功能需求

### 9.1 性能

| 指标 | 目标 | 备注 |
|---|---|---|
| 管理端列表查询 | P95 < 1s | 含组合筛选，单页 20 条 |
| 开放 API 提交 | P95 < 300ms | 仅受理；不含审核执行 |
| 开放 API 查询 | P95 < 200ms | 带缓存 |
| 任务端到端 | 文本 P95 < 1s；图片 P95 < 5s；视频 P95 < 60s | 不含第三方模型耗时异常场景 |
| 配置热更新生效 | < 10s | 不中断进行中任务 |
| 单项目吞吐 | 按配额可调，默认 100 QPS / 50 并发 | 可水平扩容 Worker |
| 导出 10 万条 | < 3min 异步完成 | 后台生成，站内通知 |

### 9.2 可用性与可靠性

- 核心服务可用性 ≥ 99.9%；控制面与数据面可独立部署，控制面不可用时数据面继续按最后配置运行。
- 项目级故障隔离：单项目积压、连接异常、规则异常不影响其他项目。
- 动作失败：自动重试（默认 3 次指数退避）→ 仍失败按策略转待议或进死信 → 支持手动重试。
- 引擎无状态：Worker 可随时扩容/缩容；任务状态在数据库与 Redis 中持久化。
- Redis 不可用时降级：禁用去重锁（告警），依赖数据库唯一索引；队列不可用时暂停消费并告警。

### 9.3 安全

| 项 | 措施 |
|---|---|
| 认证 | 强密码策略、失败锁定、可选 2FA、会话超时 |
| 授权 | RBAC + 项目数据权限 + 字段权限，接口层强制校验 |
| 密钥 | AES-256-GCM 加密 + KMS 托管主密钥 + 按项目派生；界面脱敏；查看需二次确认并审计 |
| API 安全 | HMAC 签名、时间戳窗口、Nonce 防重放、IP 白名单、限流 |
| SSRF | BaseURL 与回调地址白名单 + 禁止内网段解析 + 重定向次数限制 |
| 上传 | 类型白名单（按魔数校验）、大小上限、病毒扫描（可选）、对象存储私有桶 + 签名 URL |
| 注入防护 | SQL 动作仅允许参数化语句 + 语句白名单校验；模板渲染沙箱化，禁止执行任意代码 |
| 日志脱敏 | 手机号、身份证、密钥、Token 自动脱敏后入库 |
| 传输 | 全链路 HTTPS/TLS1.2+；内部组件间 mTLS（可选） |
| 备份 | 系统库每日全备 + binlog 增量；配置与密钥单独备份并加密 |

### 9.4 可维护性

- 配置版本化 + diff + 回滚 + 连接测试。
- 全链路 `trace_id` + `task_id`，日志、指标、审计三处可关联。
- 管理端提供"配置体检"：一键检查未测试连接、空路由、超配额、异常规则。
- 提供项目模板（新建项目时可选模板，快速复制一套配置）。

### 9.5 数据保留

| 数据 | 保留策略 |
|---|---|
| 回收站对象 | 默认 30 天（7~365 可配），过期自动清理或通知 |
| 审核任务明细 | 热数据 90 天，之后归档（冷存 1 年可配） |
| 动作执行日志 | 30 天 |
| 审计日志 | ≥180 天（可配，建议 365 天） |
| 媒体文件 | 默认 30 天（可配），任务归档后转低频存储 |
| 指标数据 | 细粒度 15 天，小时级汇总 1 年 |

## 10. 部署与运维

### 10.1 组件与部署形态

| 组件 | 部署形态 | 扩缩容依据 | 关键配置 |
|---|---|---|---|
| 管理后台 UI | 静态资源 + CDN | — | — |
| 控制面 API | 无状态，多副本 + LB | CPU / QPS | 系统库连接池 |
| 开放 API 网关 | 无状态，多副本 + LB | QPS / 连接数 | 限流、签名校验 |
| 审核流程引擎（调度器） | 主备或选主 | — | 项目轮询分发 |
| 项目 Worker 池 | 按项目分组，可独立扩缩 | 队列积压、CPU | 并发数、批量大小 |
| 媒体处理 Worker | 独立池（CPU/IO 密集） | 队列积压 | 抽帧并发、临时磁盘 |
| 系统 MySQL | 主从 + 读写分离 | 连接数、QPS | 最大连接数、分区维护 |
| Redis | 哨兵/集群；项目可独立实例 | 内存、连接数 | maxmemory 策略 |
| 对象存储 | 按项目目录隔离 | — | 生命周期规则 |

### 10.2 关键运维操作

| 操作 | 步骤 |
|---|---|
| 新增项目 | 创建项目 → 配置连接并测试 → 配置审核 → 灰度（小流量）→ 放开限流 → 观察 24h |
| 项目暂停 | 后台点击暂停 → Worker 停止消费 → 在途任务完成当前步骤 → 开放 API 返回 PROJECT_PAUSED |
| 连接池调整 | 修改配置 → 校验全局水位 → 热更新（新连接按新池创建，旧池在处理任务结束后关闭） |
| 队列积压处理 | 查看积压原因（模型慢/动作超时/规则复杂）→ 扩容 Worker 或调整规则 → 观察积压下降 |
| 死信处理 | 查看死信列表与原因 → 修复根因 → 批量重新入队（需确认幂等） |
| 版本升级 | 控制面先升（向后兼容）→ Worker 灰度滚动（支持新旧配置版本共存）→ 观察指标 → 全量 |
| 数据归档 | 每月初创建下月分区 → 归档 90 天前数据到冷存 → 校验后可删热分区 |

### 10.3 监控接入

- Prometheus 抓取各组件 `/metrics`；Grafana 看板（全局/项目/审核三层）。
- 日志接入日志平台，索引字段：`trace_id`、`task_id`、`project_id`、`audit_id`、`level`。
- 告警接入：P1 电话/短信，P2 企业 IM，P3/P4 日报汇总。

## 13. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|
| 项目连接过多压垮 MySQL | 全局不可用 | 中 | 项目配额 + 全局 80% 校验 + 连接池隔离 + 超限拒绝 + 水位告警 + 只读副本分流 |
| 重复任务导致重复副作用 | 业务数据错误 | 中 | Redis 锁 + DB 唯一索引 + 幂等记录 + 锁续租 + 动作幂等键（强制建议） |
| 第三方模型不稳定 | 审核延迟/失败 | 高 | 多供应商主备 + 超时/重试/熔断 + 兜底策略（默认转待议） |
| 视频审核耗时过长 | 队列积压 | 中 | 独立媒体 Worker 池 + 抽帧参数可调 + 异步进度 + 大文件优先队列 |
| 动作失败影响结果可用性 | 结果丢失 | 中 | 重试 + 死信 + 手动重试 + 待议兜底 + 失败率告警 |
| 回收站误删 | 数据丢失 | 低 | 二次确认输入名称 + 保留期 + 恢复校验 + 永久删除异步化 + 保留审计摘要 |
| 列表数据量大导致慢查询 | 后台卡顿 | 中 | 索引与白名单排序 + 分区 + 汇总表 + 归档 + 深分页限制 |
| 配置错误导致线上事故 | 全项目异常 | 中 | 保存前测试 + 配置版本化与回滚 + dry-run + 灰度放开 + 生产环境二次确认 |
| 权限配置疏漏 | 越权 | 低 | 接口层强制 project_id 校验 + 权限回归测试 + 定期权限审计 |
| 需求蔓延（计费、标注平台） | 延期 | 中 | 严格遵守本节范围，需求进入下一期排期 |
